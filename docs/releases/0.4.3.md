## 선택한 모드에서 문제 원인 찾기

- **모드 · 문제 찾기** 탭에서 이름·ID·버전·활성 상태·필수 의존성을 확인하고 검색할 수 있습니다. 파일 해시는 목록을 직접 불러올 때만 검사합니다.
- **A가 B에 의존하면 A는 비활성화할 수 있고, 활성 A에 필요한 B는 잠깁니다.** 잠긴 이유에는 B를 필수로 사용하는 모드 이름이 나옵니다. 비활성화한 JAR는 `.jar.disabled`로 보존하고 내용·의존성을 확인해 다시 활성화합니다.
- 의심 모드와 항상 유지할 메인 모드를 고르면, 필수 의존성을 전부 남기고 선택한 의심 모드만 나누어 검사합니다. 나머지 모드도 유지합니다.
- 전체 후보를 켠 재현 시도와 모두 끈 비교 시도 후, 직접 접속·플레이한 결과를 **이번 시도 성공 / 이번 시도 실패 / 판정 불가**로 알려주면 다음 조합을 제안합니다. 단일 후보 또는 여러 모드의 최소 재현 조합으로 좁히며, 찾은 후보를 제외한 추가 탐색도 지원합니다.
- 실행 중 판정하면 저장 후 정상 종료를 요청합니다. 종료 및 파일 인계 전에는 다음 시도를 준비하지 않습니다. 크래시만으로 자동 실패 처리하지 않으며, 의존성 누락은 원래 문제의 재현으로 세지 않도록 안내합니다.
- 메모·현재 차수 판정 수정·원본 로그 이력·중단·재개·원본 복귀를 제공합니다. 검사는 별도 폴더와 매 시도 **새 테스트 월드**를 사용합니다. 기존 월드에서만 발생하는 문제는 새 월드에서 재현되지 않을 수 있습니다.
- 원격 검사에는 실행기0.4.3 이상이 필요합니다. 구형 실행기는 원본 폴더 보호를 위해 검사 실행을 거부합니다. 검사 중 자동 재시작·무인 절전·운영 WebDAV 동기화·원본 설정 변경을 막습니다.

## 중단된 파일 전송 이어받기

- 연결·인증이 끊겨도 받은 파일과 청크를 보존합니다. 관리 서버 재시작 후에도 전송 기록을 복원하며 완료 파일의 해시를 확인해 재사용합니다.
- 실행기0.4.3은 파일 중간 위치부터 이어 보냅니다. 구형 실행기도 새 관리 서버에서는 완료된 파일을 다시 보내지 않으며, 전송 중이던 부분 파일만 처음부터 다시 보냅니다.
- 기존 버전의 미완료 가져오기 캐시는 현재 인증된 가져오기 요청과 파일 목록을 확인한 뒤 재사용합니다. 소유자·실행기·대상 폴더·요청·원본 파일이 다르면 덮어쓰지 않습니다.
- 마지막 완료 응답이 유실됐을 때 이미 반영한 파일을 다시 처리하지 않도록 완료 확인 기록을 추가했습니다.
- 웹과 Discord 제어 패널에 전송량·속도·예상 남은 시간을 함께 표시합니다. 속도는 최근 실제 수신 바이트로 계산하며, 재사용한 파일은 네트워크 속도로 계산하지 않습니다. 연결 대기·정체·측정 부족 시에는 ETA를 확정하지 않습니다. 예상 시간은 전송 기준이며 검증·반영 시간은 별도입니다.
- 전송 개수는 관리 서버가 확인한 수신 상태를 기준으로 표시합니다. 실행기의 늦은 진행 메시지가 완료 개수를 이전 값으로 되돌리는 문제를 막았습니다.

## 화면 안정성

- 탭을 오갈 때 실행 컴퓨터 패널이 중복되던 React 키 충돌을 수정했습니다.
- 목록·이력 페이지 처리, 명시적 새로고침, 상태 조회의 전체 메타데이터 반복 전송 제거, 모바일 탭/버튼 가로 넘침 방지를 적용했습니다.

최초 가져오기는 서버의 전체 파일을 전송합니다. 이번 변경은 중단 시 재전송 낭비와 파일 반영 비용을 줄입니다. Modrinth 검색·설치 UI는 이번 버전에 포함되지 않습니다.
