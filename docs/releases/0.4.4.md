## 파일 전송 요청 줄이기

- 작은 파일은 최대64개·요청당4MiB 이내로 묶어 보내고 받습니다. 전체 폴더를 ZIP으로 만들거나 임시 전체 복사본을 만들지 않습니다.
- 최대4개 전송 작업을 병렬로 처리합니다. 큰 파일은4MiB 청크 단위로 보내고, 동일 파일의 청크 순서는 유지합니다. 업로드·실행기 다운로드 모두 적용합니다.
- 받는 쪽에서 묶음의 전체 경로·개수·크기·오프셋을 먼저 검사합니다. 업로드 중단 시 받은 파일과 청크를 재사용하고, 마지막 해시 검증·차등 반영·원본 보호는 유지합니다.
- 구형 관리 서버에서는 기존 전송 형식으로 자동 전환합니다. 원래 회선의 업로드 속도와 디스크 속도가 낮으면 그 한계를 넘을 수는 없습니다. 변경은 새 실행기0.4.4부터 사용합니다.

## 웹에서 실행기 업데이트

- **서버 실행기 → 등록된 실행기**에 현재 버전, 업데이트 확인·다운로드 진행률·대기·재시작 상태를 표시합니다.
- **원격 업데이트 요청**은 공식 릴리스의 서명·길이·해시를 확인한 뒤 게임과 전송이 끝날 때 적용합니다.
- **전송 잠시 멈추고 업데이트**는 서명된 업데이트가 준비되면 진행 중인 업로드를 청크 경계에서 멈춥니다. 실행 중인 Minecraft는 강제 종료하지 않고 정상 종료까지 기다립니다. 받은 파일·전송 요청·dirty 상태를 남기며 supervisor 재시작 후 인계를 재개합니다.
- 기기 등록자 또는 웹 소유자만 최근 패스키 인증을 거쳐 요청할 수 있습니다. 서버 ADMIN 권한만으로 다른 사람 컴퓨터를 업데이트할 수 없습니다. 임의 다운로드 URL·쉘 명령은 받지 않습니다.
- 기존0.4.3 이하 실행기는 원격 요청 명령이 없으므로 **최초 한 번 기존 자동 업데이트 또는 최신 설치판 적용**이 필요합니다. 지원하지 않는 실행기에는 버튼을 비활성화하고 이유를 표시합니다. JAR만 직접 실행한 환경은 자동 업데이트 설치판이 필요합니다.
- 시작 준비 중에는 안전한 준비 단계를 마친 뒤 적용합니다. 시작이 보류되면 재연결 후 시작 버튼을 다시 누르세요.
- 기존 Mac·Windows supervisor의 서명 검증·시작 실패 롤백을 사용하며 기기 등록·원래 서버 경로·월드·계정을 초기화하지 않습니다.
