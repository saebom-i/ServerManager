# Server Manager 0.4.2

## 대용량 서버 파일 인계

- 중앙 관리 서버와 실행기 모두 변경·추가·삭제된 파일만 반영합니다. 변경하지 않은 파일은 기존 위치에 유지하고 서버 전체를 새 폴더로 복사하지 않습니다. 네트워크 전송은 기존처럼 변경된 파일 단위로 진행합니다.
- 같은 볼륨 안에서 변경 파일을 이동하며 이전 파일만 별도로 보관합니다. 하드링크를 사용하지 않으므로 실행 중 파일을 직접 수정해도 이전 백업이 함께 바뀌지 않습니다.
- 파일을 교체하기 전에 복구 기록을 기록합니다. 반영 실패 시 원본으로 되돌리고, 반영 중 프로세스가 중단되면 중앙 앱 시작 또는 실행기의 다음 서버 준비 단계에서 복구합니다. 중앙 웹은 먼저 열고 복구 중인 서버의 실행·파일 접근·전송을 잠급니다. 큰 서버의 복구가 설치 앱의 시작 확인 시간 초과를 유발하지 않게 합니다. 복구에 실패하면 서버를 시작하지 않습니다. 파일·폴더 교체, 빈 폴더, 삭제도 검증합니다.
- 새 변경 백업은 최근 3개와 합계 10GiB를 기준으로 정리합니다. 가장 최근 복구본 한 개는 크기가 한도를 넘어도 보존합니다. 이전 버전에서 만든 전체 백업은 자동 삭제하지 않습니다. 새 백업은 전체 서버 사본이 아니므로 `transaction.json`과 `files/`를 함께 보관하세요.
- 파일 해시 검사는 유지합니다. 전송 중 원래 파일이 바뀌거나 받은 파일의 해시가 다르면 반영을 중단합니다. 전체 해시 검사 자체가 생략되는 것은 아닙니다.

## 전송 동시성과 메모리

- 중앙 전송 잠금을 서버별로 분리해 한 서버의 검증·업로드가 다른 서버의 청크 전송을 막지 않게 했습니다. 같은 서버의 전송·반영은 계속 순서대로 처리합니다.
- 웹 파일 업로드는 64KiB 버퍼로 임시 파일에 기록합니다. 중단되거나 한도를 초과하면 기존 파일은 유지합니다. 업로드 한도는 기존 256MiB입니다.
- 편집 충돌 확인용 해시를 스트리밍으로 계산하고 텍스트 읽기·저장은 2MiB로 제한합니다.

## 적용 범위

중앙의 전송 개선은 관리 앱 업데이트 후 적용됩니다. 실행기에서 시작 전 파일을 받는 과정의 개선은 각 실행기가 0.4.2 이상으로 업데이트된 뒤 적용됩니다. 기존 실행기와의 통신 형식은 유지합니다. 실행 중인 게임과 파일 인계가 끝난 뒤 서명 자동 업데이트로 적용합니다.

이번 수정은 클래스 분리·상태 enum 전환·스레드 풀·로그 flush·강제 종료 정책을 변경하지 않습니다. 정상 종료가 지연되어도 자동으로 프로세스를 강제 종료하지 않습니다.
